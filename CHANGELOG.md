# Changelog

Every correction to published data is recorded here with a date. Nightly
appends are not listed (they are the dated release tags); corrections are.

## Unreleased

- 2026-10-16 — **Correction: OFAC records are dated by when they listed the address, not the party.** `sdn_advanced.xml` gives each party's earliest designation date, and the grade compared freezes to it. Many addresses were added years after their party was designated (six Tron addresses of a central bank carried 2010-06-16), so a freeze made before the address was public could pass as High. Listing dates now come from the git history of 0xB10C's nightly SDN extract (new `data/sdn_address_history.csv`, refreshed by `sdn`). An address first seen after the extract went nightly (2022-09-03) is dated to the day; one already in the first snapshot gets the window from its party's date to 2022-09-03, and a freeze inside that window is Moderate. Effect on frozen addresses: **41 moved from High to Moderate** (13 Ethereum, 28 Tron). The same history records removals: **183 chain-address pairs on addresses OFAC has since removed are now attributed** (91 Base, 92 Ethereum; 90 of the addresses were removed on 2025-03-21). Previously they read as "no public record". Solana listings now match the wallet that owns a frozen token account: **2 more Solana addresses** are attributed. The extract added asset codes over time (USDT 2023-05, TRX and USDC 2023-12, SOL 2026-05), so an address present when its asset's file first appeared is treated as bounded, not dated. 88 Federal Register links whose notice predates the address's listing window by more than 45 days are withdrawn (`superseded_by = withdrawn:2026-10-16`): a notice for a 2010 designation cannot have named a 2025 address. Totals: High 572 → 715, Moderate 17 → 59, unattributed 12,644 (95.5%) → 12,459 (94.2%), counted over the ledger including the 2026-10-16 nightly. Re-judgment now also triggers on a changed record date or basis, not only a changed rating, so 677 rows were superseded with their new dates. When the SDN list names an address under two asset codes, the join keeps one deterministic candidate per record, and a judgment that returns to an earlier one gets a fresh id, so re-running `attribute` writes nothing. `latest.json` gains `coverage` (per lane, read from the checkpoints), `currently_frozen_split`, `sdn_listing_lag_days` and `sdn_delisted`; `top_programs` now counts distinct addresses rather than attribution rows. `site.json` (format v2) keeps the columns the scene draws and an integer address id; addresses, transaction hashes and Solana owners move to `site_ids.json`.

- 2026-10-15 — Solana USDC freezes signed by the mint's earlier freeze authorities backfilled (`backfill --chain solana --token USDC`): 7 new rows (freezes 2022-11-11 → 2024-05-04, all signed by the 2-of-3 multisig `3sNBr7kMccME5D55xNgsmYpZnzPgP2g12CixAajXypn6`, which handed the authority to the current multisig by `setAuthority` in tx `5afAPFJqavnH6po33UU1CgxB7DaEixZoMK45jAiFD5Wx8EtemNUgAzxeXjwZ6CrT5UxYAbNEWSgGHGX8PoeTVNo1` on 2024-08-23; the mint's original authority `5TYZChz7APFopR5QirD5of4rQj1p9AXxeSAg6JndBdGj` signed none). Solana USDC coverage now starts at its first freeze, 2022-11-11, and is complete. The Solana adapter walks every authority in `authority_history`, seeded from the new `SolanaMint.prior_freeze_authorities` in `registry.py`, with per-authority cursors under `authorities` in `checkpoints.json` (the current authority keeps the top-level keys); an earlier authority walked end to end is marked `closed`. Fixes found on the way: history calls fall back to the next endpoint on `null`, an empty page or "not found" instead of reading a pruned node's answer as "nothing there"; a page with a transaction no endpoint returned no longer advances the cursors; a forward pass that reaches an authority's first transaction marks the backfill done without the extra `before` call that pruning nodes reject; `multisigFreezeAuthority` is read as the authority when the signer is a token multisig.
